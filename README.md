# ICT Harmonic Time Circle — Pine Script Framework

An institutional-grade TradingView (Pine Script v6) implementation of the
**Harmonic Time Circle** research framework: intraday New York time mapped
onto a 24-hour musical octave, overlaid with three mathematically independent
node families — the clock lattice, the pure Pythagorean lattice, and the
golden/Fibonacci phase pair — plus registered ICT windows treated as a
separate empirical layer.

The indicator is a **temporal salience engine**, not a signal generator:
geometry defines *when* evidence may deserve greater attention; liquidity,
market structure, displacement and risk logic decide *what*, if anything, to
do. No order is ever generated by time alone.

## Quick start

1. Open TradingView → Pine Editor → paste
   `indicators/HarmonicTimeCircle.pine` → *Add to chart* (intraday timeframe).
2. By default you get **Macro Tracker°-style window brackets**: a "MACRO"
   label over each registered window with a bracket that rides above the
   highs (visual technique adapted from the open-source *ICT Algorithmic
   Macro Tracker° by toodegrees*, MPL 2.0), covering the hourly :50–:10
   macros plus 15:15–15:45. A "New Pane" mode renders the windows as band
   boxes instead. Optional framework extras (off by default):
   - **Future-time rail** — the next nodes with countdowns, e.g.
     `P4 09:57:39 → TT 12:00:00 → P5 14:02:21 → φ⁻¹ 14:49:58`.
   - **Projected node lines** within a configurable look-ahead horizon.
   - **Diagnostic panel** — state (QUIET / SALIENT / QUALIFIED), nearest
     node, signed offset, salience `S_T`, comma residual `χ` with class,
     active ICT windows, confluence order, displacement reading.
   - **Background bands** only around active high-salience windows.
3. Optional: enable the **research ledger** input and create an alert with
   *"Any alert() function call"* + a webhook to accumulate machine-readable
   event records for the validation program.

All engine math runs in `America/New_York` (DST-safe) regardless of chart
symbol or exchange timezone.

## Core mathematics (exact, parameter-free)

- `T(r) = 24·log2(r)` maps musical ratios to NY times: 4/3 → 09:57:39,
  √2 → 12:00:00 exactly, 3/2 → 14:02:21.
- Golden pair `24φ⁻² = 09:10:01.86` and `24φ⁻¹ = 14:49:58.14`, symmetric
  about noon (`φ⁻² + φ⁻¹ = 1`).
- The Pythagorean comma becomes a temporal unit: `28m09.12s`; clock-vs-pure
  offsets are low-order comma fractions (10:00 vs 4/3 = +C/12, …).
- CBDR 14:00–20:00 + Asian 20:00–24:00 form an exact tangent-circle
  (arbelos) decomposition of the 14:00–24:00 parent arc.
- The golden-axis Descartes chain obeys `κ_n·R = n² + 2`, giving the
  duration hierarchy 113.31 / 56.66 / 30.90 / 18.89 min.

Full derivations: [docs/MATH_SPEC.md](docs/MATH_SPEC.md).

## Status and disclaimer

The mathematics is exact; the market relevance is **hypothesis**, per the
source paper's own framing. Timing correspondences (e.g. 09:10 vs the golden
angle) are registered candidates for testing, not validated edges.
Era-dependent windows (kill zones) ship disabled until verified against
primary ICT sources. Nothing in this repository is financial advice; see
[docs/VALIDATION.md](docs/VALIDATION.md) for how claims get promoted or
discarded.
